# PhoneBridge TLS pairing v1

## Transport

The control plane uses TCP port `17591` with a TLS server certificate generated by the persistent PC identity.

Android receives the PC SHA-256 certificate fingerprint through UDP discovery and pins that fingerprint before the TLS handshake completes.

## Application pairing

After TLS:

1. Android sends `Hello` with its persistent device fingerprint.
2. PC replies with `HelloAck` and its own identity fingerprint.
3. If the Android device is not trusted by the PC, PC sends `PairChallenge`.
4. The challenge code is derived from the first 8 hex characters of the Android identity fingerprint and formatted as `XXXX-XXXX`.
5. The user compares the code displayed on both devices.
6. Android sends `PairConfirm` only after the user explicitly confirms the matching code.
7. PC stores `Android device_id -> Android fingerprint` in its TrustStore.
8. PC returns `PairResult(trusted=true)`.
9. Android stores `PC device_id -> PC fingerprint` in its TrustStore.

The two trust stores are intentionally independent: each side remembers the identity fingerprint of the other side.

## Security boundary

Discovery is unauthenticated and must never be treated as trusted input. Its only purpose is to find a candidate PC and obtain the pinned PC certificate fingerprint.

The human pairing code is not a replacement for TLS. It protects the first-time trust decision against silently pairing with the wrong discovered device.
